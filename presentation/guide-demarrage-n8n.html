Démarrer avec n8n

Guide pour quelqu'un qui n'a jamais ouvert n8n — à distribuer après la présentation du projet git → Linear.

C'est quoi, n8n

n8n est un outil d'automatisation : on construit un workflow, une suite de nœuds reliés par des flèches, et n8n l'exécute automatiquement quand il se déclenche (sur un appel HTTP, une tâche planifiée, un clic manuel...). Chaque nœud fait une chose précise : recevoir un appel, lire ou écrire dans une API, transformer des données, tester une condition.

C'est exactement ce que fait le workflow montré dans la présentation : il reçoit les infos d'un git-sync, retrouve le ticket Linear correspondant, et met à jour son statut.

Deux façons de commencer

n8n Cloud

  • Aucune installation
  • Essai gratuit 14 jours, fonctions Pro incluses
  • 1000 exécutions pendant l'essai
  • Le plus rapide pour essayer tout de suite

En local (sur ta machine)

  • Gratuit et illimité, sans compte
  • Besoin de Docker installé
  • Tes données restent chez toi
  • Nécessaire pour rejouer la démo exacte du projet
A

Option Cloud — le plus rapide

  • Va sur app.n8n.cloud/register et crée un compte
  • L'essai gratuit donne 14 jours avec les fonctions du plan Pro
  • Une instance n8n t'es attribuée directement, accessible depuis un navigateur, rien à installer
  • Passe directement à la section Ton premier workflow plus bas
B

Option locale — avec Docker

  • Prérequis : Docker installé et démarré (docker --version pour vérifier)
  • Une seule commande officielle installe et démarre tout :
curl -fsSL https://get.n8n.io | sh
  • Le script vérifie Docker, crée un dossier ./n8n avec sa configuration, puis démarre
  • Une fois prêt, l'éditeur est accessible sur http://localhost:5678
Ce script installe un n8n générique, pour explorer l'outil. Pour reproduire exactement la démo de ce projet (webhook git-sync, nœuds Linear déjà configurés), suis plutôt docs/01-installation.md à la racine du dépôt : il utilise le docker-compose.yml du projet, avec Postgres au lieu de SQLite.

Ton premier workflow

1

Créer un nouveau workflow

  • Dans l'éditeur n8n (Cloud ou local), clique sur New Workflow
2

Ajouter un déclencheur manuel

  • Clique sur le + pour ajouter un nœud, cherche Manual Trigger
  • C'est le déclencheur le plus simple : il démarre le workflow quand tu cliques sur un bouton, sans attendre d'appel externe
3

Ajouter un nœud Edit Fields

  • Clique sur le + à la sortie du déclencheur, cherche Edit Fields (Set)
  • Ajoute un champ, par exemple message avec la valeur Bonjour depuis n8n
  • Ce nœud fabrique ou transforme des données, exactement comme le ferait un nœud de la démo qui prépare les infos avant d'appeler Linear
4

Exécuter et vérifier

  • Clique sur Execute workflow en bas de l'éditeur
  • Les deux nœuds s'allument en vert, et le résultat (ton champ message) s'affiche dans le panneau de droite
  • Si un nœud reste gris ou passe en rouge, clique dessus : le panneau de droite affiche l'erreur précise.

Questions probables

C'est payant ?
En local, non : l'auto-hébergement est gratuit et illimité pour un usage interne (licence fair-code). n8n Cloud a un essai gratuit de 14 jours puis des plans payants si tu veux continuer sans gérer de serveur.
Cloud ou local, lequel choisir pour essayer ?
Cloud si tu veux juste voir ce que ça donne en 5 minutes, sans rien installer. Local si tu veux un outil que tu gardes gratuitement après l'essai, ou si tu veux rejouer la démo exacte du projet.
Je peux changer d'avis plus tard et passer de Cloud à local (ou l'inverse) ?
Oui, un workflow s'exporte en JSON et se réimporte ailleurs — rien n'est enfermé dans l'un ou l'autre.
